# QA ledger

QA part 1: release hygiene, data safety, stability. Not fast mode.

**Rules.** Every finding has a row and keeps it after it is fixed (with the commit hash). A row says PASS only with evidence: a test name, command output, or a screenshot path that was actually viewed. Anything not verified is UNVERIFIED with the reason. Statuses: OPEN, FIXED, PASS, ACCEPTED (justified), UNVERIFIED. Severity: blocker / major / minor (`info` for a check that passed).

**If interrupted:** read this file, find the first unchecked step in the checklist, and continue; never redo a finished step. The helper script is not part of the repo; rows are plain Markdown.

## Release symbol check (QA 1.6)

`scripts/release_symbol_check.py <Products dir>` (in the repo; run it before every release). It reads every `#if DEBUG` block of the shipped sources
(79 blocks in 36 files), collects the 265 names and 68 strings (launch flags, keys) that exist only inside them, and looks for them in every Mach-O of
the build: `strings` of each binary minus the names it only imports, matched as Swift-mangled identifiers (`<length><name>`), whole words and whole
strings. The brief's names are also looked for as plain substrings.

Command and result, Release, iOS device (`xcodebuild build -configuration Release -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO`):
